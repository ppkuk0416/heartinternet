# HearthDeck Hub Product Brief

작성일: 2026-06-07  
상태: Technical alpha 기준 제품 의사결정 문서

## 1. 제품 발견 요약

### 해결할 문제

하스스톤 유저는 온라인에서 덱을 발견해도 다음 질문에 다시 답해야 한다.

1. 이 덱이 현재 패치에서도 유효한가?
2. 실제 성적이나 출처를 믿어도 되는가?
3. 내 실력과 플레이 목적에 맞는가?
4. 어떻게 운영하고 어떤 카드를 멀리건해야 하는가?
5. 게임에 넣을 수 있는 정확한 덱 코드는 어디 있는가?

기존 경험은 통계, 게시글, 대회 결과, 영상과 덱 코드가 분산되어 있어
`발견 -> 신뢰 판단 -> 이해 -> 복사 -> 플레이`가 끊긴다. HearthDeck Hub는
이 흐름을 하나의 덱 상세 페이지에서 끝내는 제품이다.

### 핵심 사용자

| 사용자 | 주요 상황 | 가장 중요한 진전 |
| --- | --- | --- |
| 복귀·초보 유저 | 무엇을 만들고 연습할지 모름 | 내 목적에 맞는 현재 패치 덱을 선택 |
| 일반 등급전 유저 | 새 덱을 빠르게 시험하고 싶음 | 근거를 확인하고 코드를 즉시 복사 |
| 숙련·경쟁 유저 | 랭커·대회 덱을 빠르게 추적 | 출처와 패치를 확인한 최신 리스트 확보 |
| 덱 기여자 | 본인 덱과 운영법을 공유 | 유효한 코드와 경험을 신뢰 가능한 형태로 게시 |
| 운영자 | 외부 덱 신호를 큐레이션 | 검증 가능한 후보만 공개 덱과 연결 |

초기 주 사용자는 한국어 정규전 유저다. 야생·변칙, 글로벌 다국어, 카드
컬렉션 기반 추천은 후속 범위다.

> 현재 패치에 맞는 덱을 골라 운영법을 이해한 뒤 게임으로 바로 가져가고 싶다.

### 한 문장 제품 비전

> 현재 패치에서 믿고 쓸 덱을 발견하고, 이해하고, 한 번에 복사하는 가장 빠른
> 하스스톤 덱 커뮤니티.

## 2. 차별화 전략

HearthDeck Hub는 가장 큰 통계 DB나 가장 큰 자유 게시판과 정면 경쟁하지 않는다.
초기 차별화는 아래 세 가지다.

1. **복사 가능한 결정 단위**: 모든 공개 덱은 유효한 코드, 패치, 직업,
   30장 구성과 함께 제공한다.
2. **근거의 등급화**: 작성자 주장, 원본 출처 연결, 운영진 확인을 분리한다.
   승률은 승·패 원자료 없이 입력할 수 없다.
3. **설명 가능한 최신성**: 현재 패치 여부와 최근 외부 관측 출처 수를 보여주되,
   내부 점수를 승률처럼 표현하지 않는다.

### 경쟁 대안과 포지셔닝

| 대안 | 강점 | 사용자가 겪는 공백 | HearthDeck Hub의 선택 |
| --- | --- | --- | --- |
| 대규모 통계 사이트 | 방대한 플레이 데이터와 메타 집계 | 초보자가 수치의 맥락과 운영법을 해석하기 어려움 | 신뢰 근거와 실제 플레이 가이드를 한 화면에 결합 |
| 덱 빌더·게시판 | 자유로운 공유와 토론 | 오래된 코드, 과장된 승률, 품질 편차 | 게시 전 코드 검증과 구조화된 가이드 |
| 대회·랭커 집계 사이트 | 경쟁 덱 발견 속도 | 한국어 설명과 초보 적합성 부족 | 공식 이벤트 검증, 출처 보존, 한국어 큐레이션 |
| 영상·SNS·커뮤니티 글 | 생생한 맥락과 최신 반응 | 덱 코드와 핵심 정보가 콘텐츠 안에 묻힘 | 원문을 보존하면서 복사 가능한 덱 레코드로 정리 |

## 3. 제품 원칙

1. 덱 코드 복사는 항상 가장 가까운 주요 행동이어야 한다.
2. 최신과 인기보다 먼저 “왜 믿을 수 있는지”를 설명한다.
3. 승률을 추정하거나 외부 관측을 성적처럼 포장하지 않는다.
4. 초보자에게는 숫자보다 추천 대상, 난이도, 멀리건, 약점을 먼저 보여준다.
5. 외부 수집 결과는 자동 게시하지 않고 검증 큐를 통과시킨다.
6. 커뮤니티 기능은 덱 선택과 개선에 기여할 때만 추가한다.

## 4. 핵심 가설과 검증

| 가설 | 현재 증거 | 다음 검증 |
| --- | --- | --- |
| 패치·출처 표시가 덱 선택 불안을 낮춘다 | 제품 설계 가설, 사용자 검증 없음 | 5명 사용성 테스트에서 신뢰 판단 이유 관찰 |
| 구조화된 가이드가 초보자의 복사 결정을 돕는다 | 제품 설계 가설 | 가이드가 있는 덱과 코드만 있는 덱의 복사율 비교 |
| 최근 외부 관측 덱이 재방문 이유가 된다 | 수집·트렌드 시스템 구현 | 주간 재방문율과 트렌딩 진입 후 복사 증가 측정 |
| 4단계 등록은 품질을 높이면서 완료 가능하다 | 기능 구현, 퍼널 데이터 없음 | 시작 대비 초안 저장·게시 완료율 측정 |

구현 완료는 가설 검증 완료를 의미하지 않는다. 실제 사용자 데이터가 생기기
전에는 위 가설을 사실로 표현하지 않는다.
