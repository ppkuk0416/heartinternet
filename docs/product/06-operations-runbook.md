# Public Beta Operations Runbook

상태: 기술 알파 운영 기준  
오너: Product / Operations / Engineering  
기준일: 2026-06-09

## 목적

HearthDeck Hub의 핵심 약속인 `현재 패치의 신뢰할 수 있는 덱 발견 -> 판단 ->
복사` 흐름을 유지하기 위한 최소 운영 절차를 정의한다. 자동 수집은 후보를
만들 뿐이며, 공개 여부와 근거 라벨은 운영자가 최종 책임진다.

## 일일 점검

운영자는 매일 다음 순서로 확인한다.

1. `/admin/operations`에서 수집, 후보 큐, 신고, 카드 데이터, 패치, 분석 상태를 확인한다.
2. `/admin/content-readiness`에서 현재 패치 덱 수와 직업 분포를 확인한다.
3. 신규 후보를 원문, 코드, 패치와 대조해 승인·반려·기존 덱 연결한다.
4. 신고 큐에서 개인정보 노출, 피싱, 악성 링크를 우선 처리한다.
5. 분석 이벤트가 24시간 이상 끊겼는지 확인한다.

## 최근 덱 수집 장애

- 6시간 동안 신규 수집 실행이 없거나 최근 실행이 실패하면 `P1` 운영 장애로 본다.
- 특정 소스만 실패하면 해당 소스를 비활성화하고 다른 소스의 수집은 유지한다.
- 원문 형식 변경이 의심되면 자동 파서를 수정하기 전 dry-run 결과를 보존한다.
- 수집 재개 후 중복 코드, 잘못된 패치, 정규전 유효성을 다시 확인한다.
- 미검토 후보를 장애 복구 목적으로 자동 공개하지 않는다.

## 패치 전환

1. 공식 Blizzard 공지의 패치 번호와 적용 시각을 확인한다.
2. 카드 회전 또는 대규모 밸런스 변경이면 카드 적법성 설정을 먼저 검토한다.
3. `npm run patch:check` 결과와 관리자 상태를 대조한다.
4. 승인된 전환만 `npm run patch:activate`로 적용한다.
5. 이전 패치 후보가 stale 처리되고 트렌드 신호가 재계산됐는지 확인한다.
6. 현재 패치 공개 덱이 30개 미만이면 콘텐츠 준비 상태를 공개 베타 미달로 표시한다.

## 공식 대회 덱

- Blizzard 공식 기사 ID, URL, `Esports` 카테고리를 확인한다.
- 운영자 매니페스트는 먼저 dry-run하고 경고가 남아 있으면 쓰기 실행을 금지한다.
- 기사에 구조화된 덱 목록이 없으면 코드를 Blizzard 검증으로 표시하지 않는다.
- 후보는 일반 후보와 동일하게 운영자 검토를 거쳐야 공개된다.

## 신고와 콘텐츠 안전

- `P0`: 개인정보 노출, 피싱, 악성 코드, 계정 탈취 링크
- `P1`: 혐오·괴롭힘, 반복 스팸, 명백한 허위 출처
- `P2`: 덱 품질 이견, 불완전한 가이드, 중복 콘텐츠

`P0`는 우선 숨김 후 사실 관계를 확인한다. 모든 기각·검토중·숨김 처리는
감사 로그를 남긴다. 단순 반대 의견이나 덱 취향 차이는 숨김 사유가 아니다.

## 장애 등급과 대응

| 등급 | 예시 | 목표 대응 |
| --- | --- | --- |
| P0 | 로그인 불가, 덱 코드 노출, 잘못된 코드 공개, 데이터 손상 | 즉시 기능 중단 또는 롤백 |
| P1 | 복사·게시 실패, 수집 전면 중단, 신고 큐 접근 불가 | 당일 원인 확인과 완화 |
| P2 | 일부 필터·표시 오류, 단일 소스 실패 | 다음 운영 주기 내 수정 |

장애 이슈에는 발생 시각, 영향 범위, 임시 조치, 원인, 재발 방지, 검증 결과를
기록한다.

## 배포와 롤백

1. `lint`, `typecheck`, 단위 테스트, DB 검증, 프로덕션 빌드, 보안 감사를 통과한다.
2. 스테이징에서 로그인, 등록, 게시, 발견, 상세, 복사, 댓글, 신고를 확인한다.
3. DB 마이그레이션은 애플리케이션 배포 전에 호환성을 검토하고 되돌릴 SQL을 준비한다.
4. 치명적 회귀가 있으면 이전 배포로 롤백하고 쓰기 기능을 필요한 범위만 잠근다.
5. 복구 후 사용자 흐름과 운영 대시보드를 다시 확인한다.

## 개인정보와 비밀값

- raw 덱 코드, 이메일, 댓글 본문을 제품 분석 이벤트에 기록하지 않는다.
- 익명 이벤트는 일일 HMAC 식별자를 사용하고 원본 IP를 DB에 저장하지 않는다.
- Supabase service role, 해시 비밀값, 배포 토큰은 저장소에 커밋하지 않는다.
- 공개 베타 전 분석 이벤트, 신고, 감사 로그의 보관 기간과 삭제 담당자를 확정한다.

## 공개 베타 승인 증거

다음 자료를 GitHub 이슈에 첨부하고 승인한다.

- 스테이징 핵심 흐름 E2E 결과
- 현재 패치 30개, 8개 직업, 신뢰 덱 10개, 초보 덱 5개 충족 화면
- 외부 오류 추적 테스트 이벤트
- 5명 사용성 테스트 결과와 주요 수정 사항
- 백업·복구 또는 롤백 리허설 기록
